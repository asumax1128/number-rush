# 未解決事項と検証計画
更新: 2026-10-23。**この文書の論点は未解決。**

## P0: 完全保証の実現可能性
1. SAFE STATEを形式化する: 状態=(盤面6個体、公開5枚、予約キュー、現在とNEXTのMISSION/TARGET、残り時間、シード状態等)。許容行動は全合計一致ルートおよび許可REFRESH。
2. G1〜G4のうち、G4は無限継続の不変条件が必要。有限深さ探索だけで「厳格完全保証」と宣言しない。
3. 全合計一致ルートを保証すると、TARGET CLEARの多さが生成候補を減らす。安全状態集合の存在・十分な多様性を実験で測定。
4. 公開5枚だけで最大6枚消費する場合、予約6枚目の値が結果に影響。生成確定順を仕様化。
5. REFRESHで公開キューを最大5枚消費し、公開情報がシフトしたときのNEXT予告維持を検証。
6. 安全なREFRESHが0種類の状態で、報酬の実用性・UI・ストックの扱いをどうするか。
7. 無期限保証が成立しない場合の仕様変更案をユーザーへ提示し、独断で救済・問題書換えを行わない。

## P1: 問題・難易度
- 各MISSIONの厳密な数学的述語、EASY/NORMAL/HARDへの割当、元数字/実効値判定を確定。
- タイル値の範囲、TARGET範囲、REVERSEを含む負の合計、TARGET=0の可否を決める。
- 同難易度帯で降格する順序と、最終的な生成不能時の挙動を決める。
- 乱数抽選の分布、特殊タイル出現率、ミッション等級分布の実測値を測定。
- SCORE報酬とBONUS倍率の順序、TIMEの上限境界、CHAIN上限超過点をテスト。

## P1: 競技バランス
- 60秒の実プレイを計測。MISSION CLEAR重視／選択的TARGET CLEAR／高速TARGET CLEARの3戦略で得点を比較。
- 正解・TARGET CLEAR・MISSの平均所要時間、CHAINの維持率、報酬の寄与を測定。
- ゲージ境界（4→5、9→10、19→20、29→30）を重点テスト。
- MISS時のタイマー−1秒と通常経過時間の重複処理を確認。

## P2: UI/UX
- REFRESH不可理由の表示位置と、選択中のタイマー継続。
- EASYの情報簡略化、ボタン強調のアクセシビリティ。
- 回答後の選択解除、連打・二重確定防止、入力ロック時間。
- NEXT予告の見せ方、BONUS/DOUBLE/REVERSEの識別。
