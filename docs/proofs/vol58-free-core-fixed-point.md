# NUMBER×RUSH Vol.58｜FREE安全核の無限G4固定点：構成的証明と条件（暫定）
日付: 2026-10-23

## 1. 状態・記号
Vol.41/57の有限検証モデル：6個の位置付きタイル。各タイルは数字1,2,3とNORMAL/DOUBLEの組（6種類）。ボード`b∈{0,...,5}^6`、予約済み6タイルキュー`q∈{0,...,5}^6`。TARGET `t`は現在のボードで少なくとも1つの非空部分集合から得られる正整数。MISSIONはFREEに固定する。タイル補充は消費した位置の昇順。消費枚数kのときqの先頭k枚を補充し、消費されなかった予約キューの残りと、後続で新規生成する予約タイルから次の6枚キューを作る。
`A(b,t)`：TARGET一致のすべての非空選択部分集合（MISSION CLEAR/TARGET CLEARの区別はFREEではない）。`b'=T(b,q,a)`。
`H(b)`：ボードbで非空部分集合の和として作れる全FREE TARGET集合。
`C(b,q,t)=⋂_{a∈A(b,t)}H(T(b,q,a))`：すべてのTARGET一致回答分岐で共通して成立するNEXT FREE TARGET候補集合。

## 2. Vol.57の全件探索結果
`tools/verify-vol41.cpp`は全46,656ボード×全46,656予約キューに対して、現在TARGETが成立するすべての状態で`C(b,q,t)≠∅`を検査した。Vol.55先頭24区間＋Vol.57残り168区間で全192区間をローカル完走、FREE zero=0。合計2,176,782,336ボード×キュー組、35,474,889,600 TARGET状態、137,137,287,168 TARGET一致ルート。詳しくは`docs/reports/vol57-full-local-coverage.md`。

## 3. 固定点構成
`K_FREE={(b,q,t,FREE): b∈B, q∈Q, t∈H(b)}`。
全件結果から、任意の`s=(b,q,t,FREE)∈K_FREE`に対し、`t'∈C(b,q,t)`を選べる。任意の合法回答`a∈A(b,t)`に対し、`t'∈H(b')`である。
回答後のキュー更新が、予約済みキューの未消費部分を変更せず、後続タイルを同じ6種類から補充するなら、**どの次キュー`q'`が生成されても**`q'∈Q`。したがって`(b',q',t',FREE)∈K_FREE`。
ゆえに`K_FREE⊆Pre(K_FREE)`であり、`K_FREE`は安全作用素の後固定点。状態空間が有限なので、帰納法または最大固定点の性質から**この限定モデルでは任意の有限ターン数にわたりFREEを選び続けることで安全に継続できる**。

### タイミングに関する注意
公開NEXT TARGETは現在の回答より前に固定され、全回答分岐に共通する`t'`を選ぶ。上の`C`の共通部分演算はこの条件を満たす。公開済みキューは変えず、回答後に未公開の末尾のみ生成する。新規末尾はどの値でも次状態の`K_FREE`に含まれるため、FREE核の閉包性を損なわない。

## 4. 重要な保証範囲
- この論証は**Vol.57で実際に検証されたC非空という補題を正しいものとした場合の数学的帰結**。独立した別の全192区間固定点実装を走らせたわけではない。
- **FREEのみ**の閉核を証明する。PAIR/TRIPLE/ODD/EVENを好きな頻度で出せる保証ではない。別MISSIONを公開するときは全回答分岐が`K_FREE`へ戻ることを個別に証明する。
- タイル種類は数字1〜3・NORMAL/DOUBLEの6種類に限定。BONUS（数値がNORMALと同じなら安全性について射影可能な場合がある）、REVERSE、数字4〜9、REFRESH、他MISSION、スコアや時間、実ゲームの別キュー生成規則は未証明。
- Vol.41のキューは予約6枚。実ゲームの公開5枚＋内部予約6枚目は同じ先頭6枚が不変なら表現できるが、公開タイミング・予約6枚目の生成時刻や未公開部分の処理が一致することを実装で確認する必要がある。
- 安全核の存在は多様なMISSIONの出題品質やG3を保証しない。FREEへの退避は理論的な安全装置であり、FREEばかり出す運用を意味しない。
