# Vol.31｜任意予約キューでのFREE・PAIR G4閉包性
日付: 2026-10-23
状態: **すべて暫定案・未正式承認**。限定モデルに関する条件付き構成的証明。実ゲームのG4は未証明。

## ユーザー選択
- G4はまずFREE・PAIRのみで予約キュー固定点を構築。
- 回答後の未公開末尾生成候補を全列挙して安全性を確認。
- ODD・EVEN出題可能率統計は直近100問を基本窓にする。
- ODD/EVEN補正上限1.25倍、難易度別MISSION CLEAR解法数帯（EASY3〜8/NORMAL2〜5/HARD1〜3）、同種MISSION連続回避ソフト制約を維持。

## 状態とタイミング
B=6枚の盤面、Q=予約済み6枚（先頭5枚公開、6枚目非公開確定）、T=現在TARGET、M=現在MISSION∈{FREE,PAIR}。
NEXT TARGET/MISSIONは現在回答前に公開し固定する。現在TARGET一致の全非空部分集合（MISSION未達TARGET CLEAR含む）を検査。
回答でk枚消費後、Qの先頭k枚を消費位置昇順に補充。残ったQ[k..5]は変更不可。回答後に未確定の末尾k枚を生成して新たな6枚予約Q'を作る。NEXT TARGET/MISSIONは変更不可。
実ゲームのREFRESH、特殊タイル、他MISSIONは対象外。

## 独立全探索（今回実行）
数字1〜2限定、6枚盤面B∈{1,2}^6、予約Q∈{1,2}^6。
- 盤面×予約: 2^12=**4,096**。
- 現在TARGETに合計一致ルートが存在する(B,Q,T): **36,480**。
- 全回答ルート後の盤面で共通してFREEを解けるNEXT TARGETが存在しない状態: **0**。
- 同様にPAIRを解けるNEXT TARGETが存在しない状態: **0**。
- NEXT FREE候補総数（全状態合計）: 309,616。
- NEXT PAIR候補総数（全状態合計）: 92,636。
この数値は今回Pythonで全列挙した結果。TARGETは盤面の非空部分集合和で定義。タイル位置IDを区別。

## 数字1〜3へのG4拡張：Vol.30の結果を前提とする条件付き構成
Vol.30では、数字1〜3、任意B∈{1,2,3}^6、任意Q∈{1,2,3}^6、全解答可能TARGETの6,234,408状態に対し、全合計一致ルート後で共通NEXT PAIR TARGETが存在しない状態は0と報告済み。
K={(B,Q,T,M): B,Q∈{1,2,3}^6, M∈{FREE,PAIR}, 現在MISSION CLEARが存在する}。
任意S∈Kについて、Vol.30の共通NEXT PAIR TARGET t'を回答前に選択すれば、どのTARGET一致ルートaの後も新盤面B'でPAIR(t')が成立する。
回答後の未公開末尾をどの合法な数字1〜3で埋めても、新予約Q'は{1,2,3}^6の元なので(B',Q',t',PAIR)∈K。
したがってKは生成側がNEXT PAIRを選ぶ戦略に対して閉じており、数学的帰納法により無期限継続できる。
この論証は**Vol.30の全件計算の正しさを前提**とし、数字1〜3の全件独立再実行は今回行っていない。全件再現テストとCI化が望ましい。
NEXT FREEもVol.30の共通候補0件なしを使って安全に選択可能。ODD/EVEN/TRIPLEの安全なNEXTを選ぶには、それぞれのMISSION成立状態もKへ追加し、後続の閉包性を検証する必要がある。

## 量化順序（重要）
∃(NEXT MISSION,TARGET) [現在の回答前に確定]、∀現在TARGET一致回答a、∀合法な未公開末尾生成g（今回のKは全Qを含むため）、遷移先∈K。
未公開末尾の生成は回答後に行う。予約済みQを回答後に書き換えてはならない。

## ODD・EVEN統計：直近100問の暫定案
- 直近100問について、各MISSIONがSafety Engine通過候補として出題可能だったかを1問単位で記録する。
- 分母は各MISSIONの出題可否を判定した問題数（最大100）、分子はそのMISSIONの安全候補が1つ以上あった問題数。
- 同時に実際に選択されたMISSIONの出題率を別集計する。出題可能率と実出題率を混同しない。
- p=可能回数/判定回数。補正係数=min(1.25,1/max(p,epsilon))。出題不可能MISSIONには補正を適用しない。
- 少数サンプルでの暴れを抑えるため、ウォームアップ（例20問未満は倍率1.0）と平滑化は次回承認待ち。
