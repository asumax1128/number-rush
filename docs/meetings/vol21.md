# Vol.21｜SAFE COREの構成とCHALLENGE STATE（Ver.0.20案）
日付: 2026-10-23
状態: **全項目暫定・未正式承認**。限定モデルの構成的証明のみ。全ゲームの完全保証は未証明。

## ユーザー選択の暫定方針
1. Safety Engine と Variety Engine を分離。
2. 同種MISSIONの連続回避はソフト制約。安全性を優先して連続を許可。
3. 最初のSAFE STATE検証モデルはFREEのみ。
4. 会議内容は毎回 asumax1128/number-rush に保存する。

## 今回の構成的証明（FREE限定）
任意の正整数 k を固定する。
- 6つの盤面タイルはすべて通常タイル、元数字・実効値ともk。
- TARGET=k、MISSION=FREE。
- NEXT TARGET=k、NEXT MISSION=FREE。
- 公開5枚、内部予約、および将来生成するタイルはすべてk。
- 合計一致する非空タイル集合は**1枚のみ**（k>0なので2枚以上は合計が2k以上）。
- 6つのタイルIDそれぞれに対して、1枚消費→1枚kを補充→元の同型状態に戻る。
- よってこの限定状態集合は回答遷移について閉じており、任意回のMISSION CLEARを継続できる。

この証明は、キューの将来生成規則を「常にk」に限定し、MISSION FREEのみ、特殊タイルなし、REFRESHを使わない場合のもの。全モード、全ミッション、REFRESHを含む完全保証ではない。REFRESHを含めるには、許可交換後の遷移も別途示す必要がある。

## 新提案（未承認）
- SAFE CORE: 無期限の継続保証を数学的に示せる状態集合。
- CHALLENGE STATE: 多様な数値・解法を含み、全合計一致ルートの先で安全集合へ合法に継続できると**証明された場合に限り**採用する状態。
- いわゆる「緊急時にSAFE COREへ戻す」操作は、公開済みNEXT TARGET/MISSION/QUEUEと予約キューの変更を伴うなら禁止。
- Safety Engineは安全性の検査、Variety Engineは安全な候補の難易度・解法数・数字多様性・連続MISSION回避を評価。
- SAFE COREが非空であることと、豊富なCHALLENGE STATEを持てることは別の主張。後者は未検証。

## 次回の検証候補
- k固定SAFE COREから1遷移で戻れる状態の探索。
- 小さな数字集合（例1〜3）で状態を列挙し、安全な拡張の存在性を確認。
- 公開キュー・予約キューを状態に含め、公開情報の固定を守る。
- REFRESHの許可交換が0種類になる状態のUXと報酬価値。
